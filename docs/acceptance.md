# 验收标准

先确认用户能完成操作，再确认动效关系与细节。以下自动化阈值用于本次参考片的回归，不是所有产品的像素误差标准。

| 条款 / 检查 | 验收方法 | 本项目覆盖 |
|---|---|---|
| LM-01 语义共同运动 | 稳定底板对齐后观察内部相对位置 | 源帧追踪；负一屏同排保持统一 transform |
| LM-02/03 分层收稳 | 同一时刻独立测量各层；区分等待与尾段 | 五层 CSV 对照 DOM；进入 X 的 RMS < 8 px |
| LM-04 克制收尾 | 逐帧检查终点附近，确认最终静止 | 原帧轨迹 + 弹簧收敛测试 |
| LM-05 几何独立 | 测量单个控件尺寸和中心间距 | 控制中心中心误差 RMS < 6 px；退出分别比较尺寸与间距 |
| LM-06 背景层次 | 确认背景/前景有独立通道，文字可读 | 通道实现 + 视觉检查；不构成完整对比度审计 |
| LM-07 双向设计 | 分别记录进入与退出曲线 | 负一屏退出 X 的 RMS < 16 px；原帧对照 |
| LM-08 改向连续 | 改目标前后立即采样 x/v、取消旧延迟 | 浏览器逐层精确相等；快速反向测试 |
| LM-09 直接操纵 | 真实拖动、松手、短程反向 | 真实鼠标测试 + 拖动中分层跟随 |
| LM-10 时间一致 | 不同步长推进到同一时间；暂停后截图/坐标不变 | 24/60/90/120 Hz；三种阻尼；逐帧冻结 |
| LM-11 减少动态效果 | 改系统设置后触发状态，检查延迟与目标 | Playwright reduce 模式，即刻到位且清除延迟 |
| LM-12 非手势操作 | 键盘遍历、打开/关闭、滑块与焦点 | 按钮、Esc、滑块自动化；完整屏幕阅读器审计仍由采用方完成 |
| 证据完整 | 索引、PTS、帧数、校验和、来源链 | `check-evidence.mjs`；`archive.py verify` |
| 静态发布 | 项目子路径、移动布局、视频范围请求、图片与文档链接 | 构建站点浏览器测试 + 链接检查 |

最新本地实测结果由测试写入 [交互结果](../analysis/browser-checks/results.json)、[前景结果](../analysis/inner-motion/browser-validation.json) 与 [检查器结果](../analysis/inner-motion/inspector-validation.json)。CI 的实际运行状态以 GitHub Actions 为准。

## 人工验收步骤

1. 正常速度完成打开 → 关闭 → 再打开；检查主要内容是否及时可用。
2. 以 1/4 速度检查每层尾段、控件尺度与留白，确认语义单元未被拆散。
3. 在早期、中段、接近终点时反向，检查是否跳位、停顿或旧动作重新出现。
4. 拖到一半释放、拖回、再次进入，检查状态与可见位置是否一致。
5. 打开减少动态效果，重复核心操作；用键盘完成相同任务。
6. 在目标设备记录至少 30 次操作的帧间隔、视口和刷新率，并另查真实触摸与辅助技术体验。

测试轨迹通过不等于逐像素复刻，也不等于完整的生产可访问性认证。原型中的静态桌面、应用内容简化和参考素材授权范围分别见实现与媒体说明。
