# 参与与版本规则

欢迎补充新的逐帧研究、改进交互或提出规范修订。先说明具体观察或可重现的问题，再说明改变后的行为。

## 提交设计修改

标明修改涉及的 LM 条款，并提供对应原片时间段、坐标单位、原始观察和推断。审美判断可以讨论，不应被写成已经验证的用户感知事实。新场景可以采用不同参数，说明语义分组与时序理由即可。

## 提交实现修改

运行 `npm test`。改动控制中心或负一屏路径时，检查进入 / 退出、拖动、反向以及减少动态效果。别把同一卡片内部拆成无依据的逐图标延迟。

拟合数据经 `scripts/fit_foreground_motion.py` 生成，随后用 `node scripts/export-tokens.mjs` 同步公开预设。对新生成的证据先审查差异，再运行 `node scripts/inventory-evidence.mjs` 更新哈希清单。

## 素材与档案

新录屏请注明来源、时间、尺寸、实际 PTS 与可分享范围。不要引入账号凭证、个人通知或原工作站绝对路径。原片保存为新 Release 附件，保留 SHA-256；修改旧研究结论时保留先前版本。

0.x 版本允许规则演进。改变 MUST 行为或预设合同至少提升次版本；修正文档措辞、链接或不改变行为的错误可提升补丁版本。为每次发布记录范围、验证方式和已知限制。
